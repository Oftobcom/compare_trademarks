Проанализировал все 5 версий. Эволюция линейная и логичная:

### Анализ v01 → v05

| Версия | Метрики | Параллель | Кэш | Отчеты | Препроцессинг | Проблемы |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **v01** | Только ORB + Dice `2*good/(n1+n2)` | нет | нет | консоль | resize 1200 | Много ложных срабатываний, не учитывает геометрию. `load_gray` только jpg/jpeg |
| **v02** | SIFT + FLANN + RANSAC-гомография, score = `inliers/min(n1,n2)` | нет | нет | консоль | resize 1200 | Уже на порядок лучше для товарных знаков. Но нет цвета, нет композиции |
| **v03** | **3 метрики**: SIFT + Color(HSV) + pHash(DCT) + веса `0.6/0.25/0.15` | нет | нет | CSV + `top1_matches.jpg` + CLI argparse | BGR load | Появился threshold YES, веса, визуализация. Нет ORB/SSIM, нет параллели, кэша нет |
| **v04** | **5 метрик**: + ORB + SSIM (после выравнивания) | `ProcessPoolExecutor` | pickle кэш по mtime `CachedItem` | + HTML отчет с base64 | CLAHE + GaussianBlur | Кэш ключ только по mtime (ошибка если файл перезаписан за 1 сек), нет логов в воркерах, `file_key` без размера, только `iterdir()` не рекурсивно |

**Общие узкие места всех версий:**
1. Не обрабатывают альфа-канал PNG (товарные знаки часто на прозрачном фоне) → черный фон после `imread`
2. Цвет сравнивается по всему изображению, включая белый фон → завышает Color% для разных знаков на белом
3. Нет метрики формы — критично для товарных знаков (контур, Hu-моменты)
4. Кэш v1 ломается при одинаковом mtime, нет ограничения размера
5. Нет `tqdm`, прогресс через `\r` теряется в логах
6. HTML отчет статичный, без поиска/сортировки

### Что сделано в v06

Создал финальный вариант `compare_trademarks_v06.py` на базе v05, но переработанный:

**1. 6 метрик вместо 5:**
- `SIFT%` — форма + геометрия (RANSAC + purity/confidence как в v05)
- `ORB%` — быстрая проверка
- `Color%` — HSV 36x32 + опция `--ignore-white` маскирует почти-белые пиксели (>240)
- `pHash%` — 16x16 DCT
- `SSIM%` — после выравнивания по гомографии
- `Shape%` — **новое**: `cv2.matchShapes` + Hu-моменты с exp-маппингом `100*exp(-dist*2)` → ловит схожесть силуэта, даже если SIFT слабый (минималистичные логотипы)

Веса по умолчанию: `0.35 / 0.10 / 0.15 / 0.10 / 0.15 / 0.15`

**2. Умная загрузка:**
- `load_bgr_smart()` — читает `IMREAD_UNCHANGED`, если 4 канала — композитит на белый фон (альфа → белый, а не черный)
- Поддержка всех форматов из `IMG_EXTS`
- `--recursive` для обхода подпапок

**3. Кэш v2:**
- Ключ = `путь + mtime + size + version=2`
- `is_valid()` проверяет и размер
- Атомарное сохранение, LRU-очистка до 5000 записей

**4. Производительность:**
- `ProcessPoolExecutor` + fallback `--use-threads` для Windows
- `tqdm` если установлен, иначе старый `\r` прогресс
- Инициализатор `_init_worker_logging` пишет логи воркеров в тот же файл

**5. Отчеты нового поколения:**
- CSV + **JSON** (полный дамп с метаданными)
- HTML v2: интерактивная сортировка по клику на заголовок, фильтр по имени, карточки KPI (HIGH/MEDIUM/LOW), thumbnail эталона base64, галерея **top-K визуализаций** (по умолчанию `--top-vis 3`), а не только top-1
- `top1_matches.jpg` сохраняется для совместимости + `top2_matches_*.jpg`, `top3_...`

**6. Риск-классификация:**
- `HIGH >=60%`, `MEDIUM >=30%` (настраивается `--risk-high/--risk-medium`), выводится в консоль, CSV, JSON, HTML с цветными бейджами

**7. Логирование:**
- `logging` модуль + Tee дублирование, `--log-level DEBUG/INFO`, `--log-flat`, `--no-log`

**8. CLI дополнения:**
- `--json`, `--recursive`, `--ignore-white`, `--top-vis`, `--no-preprocess`, `--use-threads`, `--risk-high/medium`

Формулы стали стабильнее: проверка на маленькие изображения в SSIM, ограничение матчей для визуализации до 150 инлайеров для читаемости.
